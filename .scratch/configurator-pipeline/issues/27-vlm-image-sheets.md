# 27: VLM에 보내는 그림을 모음 그림으로 묶기

**What to build:** 부품 탐색과 AI 판정이 VLM에 보내는 그림을, 칸을 격자로 이어 붙인 모음 그림으로 보낸다. 요청 하나에 붙는 그림 수가 VLM의 그림 수 제한을 넘지 않게 한다. Groq VLM(`qwen/qwen3.8-27b`)은 요청 하나에 3장까지만 받는데, 지금 부품 탐색은 6장을, AI 판정은 2n + 4·C(n,2)장을 보내 첫 단계에서 멈춘다(티켓 26 6절 실행 기록).

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 부품 탐색의 여섯 방향 그림이 모음 그림 한 장으로 간다. 문장에 칸 배치(몇째 줄 몇째 칸이 어느 방향에서 본 그림인지)가 적힌다
- [x] AI 판정 렌더링이 모음 그림으로 묶여 간다. 문장에 칸마다 렌더링 이름과 슬라이더 값이 적히고, 답의 `image`는 지금처럼 렌더링 이름이다
- [x] 요청 하나의 그림 수가 VLM 그림 수 제한(설정값, 기본 3)을 넘지 않는다. 모음 그림이 그보다 많으면 AI 판정을 나눠 묻고 문제 목록을 합친다(티켓 23에서 옮김)
- [x] 같은 축척으로 그린 렌더링은 모음 그림에서도 같은 축척이다(슬라이더 끝값끼리 크기 차이가 보여야 한다)
- [x] 실행기의 단계·형식 검사·다시 묻기는 바뀌지 않는다. 그림을 묶는 일은 LiteLLM 포트 안에서 끝난다

## Comments

### 2026-11-03 구현

- 모음 그림: `configurator/pipeline/image-sheet.ts`의 `imageSheets`. 그림(render.ts가 그린 8비트 RGB PNG)을 읽어 크기를 바꾸지 않고 한 장에 3×3칸까지, 칸 사이 4픽셀 회색 경계로 이어 붙인다. 320×240 칸이면 꽉 찬 한 장이 968×728이다. 칸 위치는 `{ sheet, row, column }`(1부터)이다. `render.ts`의 `encodePng`를 내보냈다.
- 부품 탐색: 여섯 방향 그림이 968×484 한 장으로 간다. `views`는 `{ from, sheet, row, column }` 목록이다.
- AI 판정: `renders`는 `{ name, values, sheet, row, column }`이다. 요청 하나에 모음 그림 `maxImages`장(9·maxImages칸)까지 보내고, 넘으면 렌더링 순서대로 나눠 차례로 묻는다. 요청마다 출력 형식의 그림 이름은 그 요청의 렌더링만이다. 답의 `problems`를 합친다. 나눈 답 하나라도 `problems`가 목록이 아니면 그 답을 그대로 돌려줘 실행기의 형식 검사로 다시 묻는다.
- 설정: `liteLlmAi`의 `maxImages`(기본 3, 1 이상의 정수가 아니면 만들 때 오류), 실행 도구는 `LITELLM_VLM_MAX_IMAGES`.
- 문서: `docs/spec-schema.md` AI 판정 절, `GLOSSARY.md` "모음 그림".
- 시험: `litellm-ai.test.ts`에 5개 더하고 2개 고쳤다. 32장(슬라이더 넷) 렌더링이 3장 + 1장 두 요청으로 가고, 둘째 모음 그림 가운데 칸이 원래 픽셀 그대로인지(같은 축척) 본다.

### 리뷰 뒤 반영과 남긴 것

- 반영:
  - 그림 수 제한이 0이나 NaN이면 판정이 끝나지 않거나 그림 없이 통과했다. 만들 때 막는다.
  - 두 지시문에 같이 들어간 모음 그림 설명을 상수 하나로 모았다.
  - 나눈 요청이 그 요청에 보내지 않은 렌더링을 짚으면 버린다. 실행기는 합친 답을 전체 렌더링 이름으로 검사해 걸리지 않기 때문이다. 모르는 이름과 `problems` 밖의 필드는 남겨 형식 검사에 걸리게 한다.
  - PNG 시그니처·IHDR을 확인하고, 그림이 없으면 빈 모음 그림 목록을 돌려준다.
  - `docs/spec-schema.md`의 LiteLLM 구현 설명을 고쳤다.
- 남긴 것:
  - 다시 물을 때 실행기가 준 `rejected`·`schemaErrors`(합친 답 기준)가 나눈 요청 모두에 간다. 실행기의 다시 묻기를 바꾸지 않는다는 요구 때문이다. 오류 문장이 렌더링 이름을 짚으므로 모델이 자기 요청 몫을 가릴 수 있다고 본다. 실제 모델에서 다시 묻기가 늘면 요청별로 나눈다.
  - 렌더링이 27장을 넘으면(슬라이더 넷부터) 끝값 렌더링과 일부 모서리 조합이 다른 요청으로 간다. 모든 렌더링이 같은 축척으로 그려져 칸 크기 차이는 요청을 넘어도 같다. 끝값 렌더링이 앞에 있어 첫 요청에 함께 들어가므로 끝값끼리는 늘 나란히 본다.
  - 부품 탐색은 나누지 않는다. 여섯 칸이 늘 한 장이고 그림 수 제한은 1 이상이다.
