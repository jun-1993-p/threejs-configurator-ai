# 18: UI 스타일 선택

**What to build:** AI가 정해진 UI 스타일 목록에서 색·글꼴·슬라이더 모양을 고르고, 고정 코어가 그 스타일로 구성기를 띄운다. 스타일은 목록 밖의 값을 만들 수 없다(ADR-0001).

**Blocked by:** 15 (LiteLLM 포트와 실제 명세 작성)

**Status:** ready-for-agent

- [x] UI 스타일 저장소에 스타일 목록이 있다
- [x] UI 스타일 단계가 목록 안의 스타일 하나를 JSON Schema 형식으로 고른다
- [x] 목록에 없는 스타일을 고르면 다음 단계로 가지 않는다
- [x] 고정 코어가 고른 스타일로 색·글꼴·슬라이더 모양을 적용한다

## Comments

### 2026-11-02 구현

- **UI 스타일 목록**: `pipeline/ui-styles.ts`의 `UI_STYLES`에 natural·dark·minimal 세 개를 넣었다. 준비 단계에서 정할 초기 내용의 자리이며, 수동 실행 도구와 시험이 메모리 저장소에 넣어 쓴다. 스타일 하나는 `{ id, summary, colors: { background, text, accent, parts }, font, slider }`이고, 슬라이더 모양 `thin`·`bold`·`square`는 고정 코어도 읽어서 `src/style.ts`의 `SLIDER_SHAPES`에 둔다.
- **스타일 고르기**: 응답은 `{ style: <목록의 id> }`이고 기존 `styleChoiceSchema`(enum)로 검사한다. 목록 밖이면 고를 수 있는 id를 붙여 다시 묻고, 3번 다시 물어도 맞지 않으면 스타일 단계에서 멈춘다. 명세 작성으로는 가지 않는다. LiteLLM 지시문에 목록 필드의 뜻을 적었다.
- **결과물**: 고른 스타일이 `style.json`으로 담기고, 붙여 넣을 div가 `data-style="style.json"`으로 불러온다. `scripts/build.ts`는 스타일 id를 넷째 인자로 받는다(생략하면 첫 스타일).
- **고정 코어**: 바탕·글자 색과 글꼴을 구성기 div와 렌더러 바탕에, 강조 색을 슬라이더와 두께 선택 슬롯에, 부품 색을 부품 메쉬에 입힌다. 슬라이더 모양마다 트랙 두께·손잡이 크기·모서리를 정한 CSS가 고정 코어에 있다. 서랍장 합성 녹화본으로 세 스타일을 만들어 Chrome에서 띄워 봤다: 바탕·부품 색이 스타일대로 바뀌고, 슬라이더는 가는 둥근 갈색(natural), 굵은 둥근 금색(dark), 각진 검정(minimal)으로 나왔다.
- 시험: `pipeline.test.ts` 3개(목록 밖 스타일은 멈춤, 다시 물은 뒤 고른 스타일이 결과물에 담김, 목록 형식 오류는 고르기 전에 멈춤). 기존 제출 시험과 `bundle.test.ts`는 `style.json`과 `data-style`을 본다.

### 리뷰 뒤 반영과 남긴 것

- 반영:
  - 고정 코어가 읽는 값 목록을 `src/`에 두는 예외를 `CODING_STANDARDS.md`에 적었다(`STANDARD_THICKNESSES` 선례).
  - 시험 이름의 "UI 스타일 저장소"를 용어집 용어인 "UI 스타일 목록"으로 바꿨다.
  - 슬라이더 클래스 이름을 `sliderClass` 하나로 만든다. `color-mix`를 모르는 브라우저가 쓸 회색 트랙을 앞에 두었다.
  - 색 필드는 `HexColor` 별칭으로 받는다. `writeProduct`는 스타일 기본값을 없애고 호출하는 쪽이 넘긴다.
- 남긴 것:
  - **UI 스타일 목록 형식 검사(`checkStyles`)**: 티켓에는 없다는 지적이 있었지만 둔다. 목록은 사람이 고치는 자료이고, 고정 코어가 그 값을 그대로 CSS와 재질 색에 넣는다. 틀린 색이나 모르는 슬라이더 모양은 브라우저에서 조용히 무시되거나 예외가 나므로, 파이프라인에서 위치를 짚어 멈추게 했다.
  - **`mountAll`이 `style.json`을 검사하지 않는다**: 명세·스윕 데이터와 같이, 고정 코어는 파이프라인이 검사한 결과물만 받는다고 본다. 손으로 고친 `style.json`은 범위 밖이다.
  - **고정 코어의 스타일 적용 시험이 없다**: 시험 환경에 DOM과 WebGL이 없어 `mount`를 부르는 시험이 원래 없다. 대신 위처럼 Chrome에서 세 스타일을 직접 확인했다.
  - **컨테이너 여백과 두께 선택 슬롯 강조 색**: 요청에 없던 것이라는 지적이 있었지만 둔다. 여백은 바탕색이 생기면서 내용이 테두리에 붙지 않게 하려는 것이고, 강조 색은 슬라이더와 슬롯이 같은 스타일을 따르게 하려는 것이다.
  - **`style`을 인자로 넘기는 것**: 후보가 바뀔 때마다 다시 고르는 값이라 `uploaded`처럼 상품 전체의 클로저 값이 아니다. 후보 하나를 도는 `writeVerifiedSpec`의 인자로 둔다.
  - **id로 스타일을 찾는 코드가 두 곳(실행기, `build.ts`)이다**: 한 줄짜리이고 찾는 목록도 달라서(저장소 목록, `UI_STYLES`) 헬퍼로 묶지 않았다.
  - **`chooseStyle`에 `structuredClone(styles)`를 넘기는 까닭이 주석에 없다**: 다른 AI 단계 입력(`parts`, `failures`, `candidate`)과 같은 관례라 따로 적지 않았다. AI 포트가 입력을 바꿔도 결과물에 담길 스타일은 그대로다.
