## Comments

### 2026-10-29 구현

- 변형 엔진(`configurator/src/engine.ts`)은 티켓 02부터 슬라이더마다 단독 스윕 보간 이동량을 기본 형상에 더하고 있었다. 코드는 그대로 두고 시험을 더했다(`test/engine.test.ts`).
  - 한 슬라이더만 움직이면: 전체 폭·전체 높이 두 슬라이더 명세의 결과가, 그 슬라이더 하나만 둔 명세의 결과와 완전히 같다. 두 슬라이더 각각 확인한다.
  - 두 슬라이더를 함께 움직이면: 교차 검증 샘플의 Fusion 형상과 점마다 비교해 형상 오차 합격선(ADR-0012, `shapeTolerance`) 안이다. 실제 오차는 1e-13 mm 정도이고, 한 슬라이더만 적용하면 37.5~112.5 mm로 실패한다.
- 교차 검증 샘플 합성 녹화본: `fixtures/synthetic/drawer.cross-checks.json`. 전체 폭(몸통·서랍의 X)과 전체 높이(몸통의 Z)는 서로 영향이 없는 쌍이다. 두 샘플 (525, 612.5), (725, 812.5)는 모두 슬라이더 범위 안이고 단독 스윕 샘플 사이 값이다. 시험이 범위 안인지도 확인한다.
  - 애드인 핵심에 `cross_check_sample(model, values)`를 더했다. 여러 파라미터를 함께 바꾼 형상을 단독 스윕 샘플과 같은 형식(`value` 대신 `values`)으로 뽑고, 바꾼 파라미터의 원래 수식을 되돌린다. 모델에 없는 이름이 있으면 아무것도 바꾸지 않고 거절한다. 단독 스윕 샘플과 같은 부분은 `_shape_or_failure`로 함께 쓴다.
  - 도구: `python -m synthetic.make_cross_checks solidcraft-test/drawer.sc --sample body_w=525,body_h=612.5 --sample body_w=725,body_h=812.5 --out fixtures/synthetic/drawer.cross-checks.json`. 파라미터를 바꾸기 전에 `SolidCraftModel.fix_baseline_layouts`로 기본 형상의 점 배치를 정해 합성 녹화본과 면·점 순서를 맞춘다.
- 고정 코어(`src/core.ts`)도 이미 명세의 슬라이더마다 행을 만든다. 브라우저로 확인했다. 두 슬라이더 명세로 결과물을 만들어 Chrome에서 열면 "전체 폭"(400~800)과 "전체 높이"(500~1000) 두 슬라이더가 생기고, 450·950으로 함께 옮기면 좁고 높은 서랍장이 그려졌다.
- 대각선 길이 함수 `diagonal`을 `pipeline/measure.ts`로 옮겨 수치 검증기와 시험이 같이 쓴다.
- 리뷰에서 반영하지 않은 것:
  - 슬라이더 UI 자동 시험은 두지 않았다. 코어가 WebGL과 DOM을 바로 쓰고 저장소에 DOM 시험 도구가 없다. 티켓 02와 같이 브라우저로 확인했다.
  - `cross_check_sample`은 티켓 08의 추가 샘플 응답을 앞당긴 면이 있다. 이 티켓의 교차 검증 샘플 녹화본을 만드는 데 필요해서 넣었다. 08이 요청 형식을 정할 때 함께 맞춘다.
  - 엔진 시험의 `maxDistance`는 수치 검증기의 것과 비슷하지만 이번 변경 전부터 있던 것이고, 면 범위를 받는 쪽과 배열 전체를 받는 쪽으로 쓰임이 다르다.
  - `Status:` 줄은 06과 같이 그대로 둔다. 분류 라벨에 완료 상태가 없다.
