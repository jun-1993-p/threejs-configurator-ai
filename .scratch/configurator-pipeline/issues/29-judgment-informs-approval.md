# 29: AI 판정은 최종 승인에 알리기만

**What to build:** AI 판정이 문제를 짚으면 지금은 그 피드백으로 명세를 다시 쓰고, 3번 실패해야 최종 승인으로 넘어간다. 티켓 26 6절 Groq 회차에서 VLM(`qwen3.8-27b`)이 멀쩡한 서랍장을 세 번 모두 오판했고(겹침·구멍·비례), 명세 작성이 그 피드백대로 끝값을 빼 메모의 폭 400~800이 420~760으로 줄어 제출됐다. 운영자 결정으로 AI 판정은 명세를 바꾸지 않고, 짚은 이유와 렌더링을 최종 승인 화면에 띄워 운영자가 판단한다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 수치 검증·축 반응·교차 검증을 통과한 명세에 AI 판정을 한 번 받는다. 문제가 있든 없든 명세를 다시 쓰지 않고 최종 승인으로 간다
- [x] 문제를 짚은 렌더링은 지금처럼 저장하고, 그 ai_judgment 피드백이 최종 승인의 `judgment`에 담긴다. 같은 렌더링을 여러 번 짚으면 이유를 이어 붙인다
- [x] 최종 승인 화면은 판정 이유를 "AI 판정이 짚은 곳"으로 보인다(3번 실패했다는 문구를 뺀다)
- [x] 처리 기록의 검증 단계에 판정 피드백이 남는다. 최종 확인 판정(`judgeRun`)이 이 모양을 읽으면 같이 고친다
- [x] `docs/spec-schema.md`의 AI 판정 절, `GLOSSARY.md`의 AI 판정을 고친다
