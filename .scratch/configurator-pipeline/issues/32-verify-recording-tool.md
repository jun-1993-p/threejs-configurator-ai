# 32: 실제 녹화본으로 검증 단계를 돌리는 도구

**What to build:** 실제 Fusion 녹화본에 명세를 붙여, AI 없이 파이프라인의 검증 단계를 실제 애드인의 추가 샘플로 돌리는 도구를 만든다. 티켓 26 선반 실물 확인에서 이 일을 scratchpad 스크립트 여섯 개로 여러 번 고쳐 썼다. 그 스크립트는 실행기(`configurator/pipeline/runner.ts`)의 `assembleAndVerify` 순서를 베껴 써서, 실행기가 바뀌면 어긋난다. 티켓 26의 남은 항목(비선형 모델, 5절 실제 상품)에서 같은 일이 다시 필요하다.

- 실행기에서 AI 없는 검증 순서(두께 후보 형상 → 조립 → 범위 → 두께 고정 실측 → 수치 → 축 반응 → 교차 검증 → 실패한 쌍의 격자 보강과 격자 검증점)를 함수 하나로 꺼낸다. 실행기와 도구가 그 함수를 함께 부른다.
- 명세를 쓰기 전에 슬라이더별 부품 반응(`sweepResponse`)을 보는 쪽도 같은 도구가 맡는다. 명세의 `affects`를 정하는 근거다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 실행기의 검증 순서를 AI·사람 포트 없이 부를 수 있는 함수로 꺼내고, 실행기는 그 함수를 부른다. 기존 실행기 시험이 그대로 통과한다
- [x] `configurator/scripts/verify-recording.ts <녹화본> <명세> --upload <업로드 ID>`가 실제 애드인(`httpFusion`)에 추가 샘플을 요청해 단계마다 피드백을 한 줄씩(슬라이더, 부품, 종류, 잰 값) 찍는다. 첫 실패 단계에서 멈추지 않고 모든 단계를 본다(실물 확인은 실패를 모으는 일이라서다)
- [x] `--responses`를 주면 명세 없이 녹화본만으로 슬라이더별 부품 반응(치수·위치 변화, 축별)을 찍는다
- [x] 애드인이 연결되지 않았으면 기다리지 않고 "Fusion 연결 필요"와 함께 끝낸다(업로드 완료 창이 열려 있으면 연결이 끊긴다). 티켓 33의 상태 파일(`data/addin-checks/serving.json`)이 있으면 그 내용도 함께 찍는다. 없으면 이 항목은 연결 필요만 알린다
- [x] 합성 녹화본과 가짜 Fusion 포트로 도구를 시험한다
- [x] `docs/recording-guide.md`에서 실물 확인 절차가 이 도구를 가리킨다

## Comments

- 2026-11-05: 티켓 26 선반 회고 3번에서 만들었다. scratchpad에 쓴 스크립트 여섯 개: 검증 단계를 돌린 `run_samples.ts`·`run_verify.ts`·`numeric_full.ts`, 부품 반응을 본 `responses.ts`, 애드인 형상을 직접 견준 `probe_box.ts`·`probe_cross.ts`.
- 2026-11-05: 구현. 검증 순서는 `configurator/pipeline/verify-spec.ts`의 `verifySpec`(실행기는 첫 실패에서 멈추고, 도구는 `keepGoing`으로 모든 단계를 본다), 추가 샘플 캐시·응답 검사는 `sampleRequester`로 실행기와 도구가 함께 쓴다. 도구는 실행기와 달리 교차 검증에 실패한 쌍을 첫 회차에 바로 격자로 보강한다. 절차는 `docs/recording-guide.md` 4-6절.
  - 리뷰에서 남긴 지적 둘:
    - "기다리지 않고"가 최대 15초 어긋난다. 서버가 애드인 소식이 끊긴 뒤 15초(`FUSION_TIMEOUT_S`) 동안 연결된 것으로 보기 때문이다. 서버의 끊김 판단을 바꾸는 일은 이 티켓 범위 밖이고 대기에 상한이 있어, 문서 4-6절에 적고 둔다.
    - 격자 쌍 상한·넣을 수 없는 격자, 앞 단계가 실패한 뒤 교차 검증을 돌려도 되는지를 도구 경로로 시험하지 않았다. 앞의 둘은 `verifySpec`의 같은 코드라 실행기 시험(`test/pipeline.test.ts`)이 이미 덮는다. 뒤의 것은 교차 검증이 녹화된 단독 스윕과 Fusion 샘플만 견주고 앞 단계 결과를 쓰지 않아 전제가 없다. 실제 녹화본에서 깨지면 그때 시험을 더한다.
