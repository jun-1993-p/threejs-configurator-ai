# 01: 애드인 업로드와 녹화

**What to build:** 운영자가 Fusion에서 CAD 애드인을 실행하면, 애드인이 서버 연결을 시험한 뒤 모델의 파라미터와 부품, 스윕을 업로드 묶음으로 보낸다. 서버는 묶음을 받아 저장하고, 같은 묶음을 테스트 데이터로 녹화할 수 있다. 이 티켓에서 정한 업로드 묶음 형식을 뒤의 모든 티켓이 쓴다(ADR-0002, 0006, 0007).

**Blocked by:** None (can start immediately)

**Status:** ready-for-human

- [x] 서버 연결 시험이 실패하면 스윕을 시작하지 않고 운영자에게 알린다
- [x] 업로드 묶음에 파라미터마다 이름·값·수식·사용자 파라미터 여부가 담긴다
- [x] 업로드 묶음에 부품(Fusion 컴포넌트 단위, 컴포넌트가 없으면 바디 단위)과 부품 이름, 부품에 속한 면이 담긴다
- [x] 사용자 파라미터마다 기본값 ±50% 범위에서 5점 균등(최소·¼·½·¾·최대)으로 단독 스윕한다
- [x] 샘플마다 꼭짓점을 메쉬 출력이 아니라 면별 (u,v) 격자로 찍고, 같은 면 구성이면 샘플끼리 꼭짓점 수가 같다
- [x] 서버가 업로드 묶음을 받아 저장하고, 녹화본으로 내보낼 수 있다
- [ ] stool1 또는 실제 상품 하나로 만든 녹화본이 있고, 실제 상품 데이터는 공개 저장소에 올라가지 않는 위치에 둔다

## Comments

### 2026-10-26 구현

- 업로드 묶음 형식: `schema/upload-bundle.schema.json`. 서버는 이 스키마와 면마다 격자 n×n 점인지를 검사한다.
- 자동 테스트: 애드인 핵심(가짜 Fusion 모델)과 서버 수신(HTTP). 실제 Fusion 어댑터와 애드인 진입점은 Fusion이 없는 환경이라 실행해 보지 못했다.
- 남은 인수 조건: 운영자가 Fusion에서 stool1(또는 실제 상품)을 업로드하고 녹화본을 만들어야 한다. 절차는 `addin/README.md`. 그동안 상태는 `ready-for-human`.
- Fusion에서 처음 돌릴 때 확인할 것: 어셈블리 프록시 면의 격자 점이 어셈블리 좌표로 나오는지, `getPointsAtParameters` 반환 형식, 재계산 실패 판정(업로드 전 오류 수 대비 증가)이 맞는지.

### 리뷰에서 나온 후속 과제 (이 티켓 범위 밖)

- 트림된 면(구멍, 원형 상판)에서는 매개변수 범위 격자의 일부 점이 면 밖에 찍힌다. 면 안팎 표시나 사상이 필요하다 — 티켓 02(구성기 띄우기) 전에 정해야 한다.
- 스윕 범위가 재계산 실패만큼 줄어들지 않는다(용어집의 스윕 범위 정의). 티켓 05에서 처리한다.
- 정수 파라미터(개수형)도 0.75배 같은 소수로 스윕된다. 티켓 10에서 개수형을 제외한다.
- 부품은 오커런스(컴포넌트 인스턴스) 단위로, 전체 경로 이름으로 구분한다. 같은 컴포넌트를 여러 번 넣은 경우(좌·우 측판)는 서로 다른 부품이 된다. ADR-0006의 "컴포넌트 단위"를 인스턴스 단위로 해석한 것이므로 확인이 필요하다.
- 루트에 바로 있는 바디는 컴포넌트가 있는 모델에서도 바디 단위 부품이 된다.
