# 33: 애드인이 추가 샘플에 답하는 상태를 파일로 남기기

**What to build:** 서버가 애드인을 "Fusion 연결 필요"로 볼 때 에이전트가 그 까닭을 가릴 수 없다. 티켓 26 선반 실물 확인에서 추가 샘플 요청이 끊김으로 끝났는데, 원인(업로드 완료 메시지 창이 Fusion 주 스레드를 막아 애드인이 서버를 찾지 못함)을 추측해 사람에게 물어야 했다. 애드인이 지금 답하는 상태를 파일로 남겨, 끊김이 Fusion이 꺼진 것인지, 주 스레드가 막힌 것인지, 애드인이 답할 업로드를 모르는 것인지를 파일로 가린다.

업로드 완료를 모달 창으로 알리는 동안에는 애드인이 답하지 못한다. 창을 띄우지 않고 알리는 방법(점검 파일과 짧은 알림)도 함께 정한다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 애드인의 일꾼 스레드가 `data/addin-checks/serving.json`에 답하는 업로드 ID(없으면 null), 마지막으로 주 스레드가 일한 시각, 마지막으로 서버를 찾은 시각, 마지막 오류를 몇 초마다 쓴다. 주 스레드가 일한 시각이 멈춰 있으면 주 스레드가 막힌 것이다
- [ ] 연결 확인 위저드(`scripts/fusion-connection-wizard.sh`)가 끊김을 알릴 때 이 파일로 까닭을 함께 찍는다. 파일을 읽어 까닭을 고르는 일은 시험 있는 Python 도구(`scripts/`)가 하고 위저드는 그 출력을 보인다. 티켓 32의 도구는 이 파일을 직접 읽는다(32에 그 항목이 있다)
- [ ] 업로드 완료를 모달 창 없이 알릴 수 있는지 정하고, 그 결정과 까닭을 ADR-0013에 적는다. 바꾸면 업로드 직후 추가 샘플 요청에 바로 답하는지 위저드로 확인한다
- [ ] 상태를 쓰는 판단(무엇을 언제 쓰는지)은 Fusion 없이 시험할 수 있는 모듈에 두고 시험한다
