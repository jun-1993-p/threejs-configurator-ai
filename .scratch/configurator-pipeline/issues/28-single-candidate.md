# 28: 구성이 하나로 정해지면 후보 하나 허용

**What to build:** 후보 제시는 서로 다른 후보 2~4개를 요구한다. 그런데 부품 탐색이 정면을 확신하고, 정보 입력이 두께 선택 노출을 정하고, 메모가 슬라이더를 하나로 정하면 서로 다른 후보는 하나뿐이다. 이때 모델은 "두께 선택 노출이 정보 입력과 다름"과 "후보끼리 모두 같음" 사이를 오가다 멈춘다(티켓 26 6절 Groq 회차, `data/runs/fallback-check/1-groq/log.json`). 운영자 결정으로 그럴 때는 후보 하나를 받는다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 후보 제시 응답의 후보 수는 1~4개다. 후보 하나로도 후보 선택으로 간다
- [x] 후보가 하나인데 정보 입력의 두께 선택 노출이 "AI 판단"이면 다시 묻는다. 두께 선택 노출로 다른 후보를 만들 수 있기 때문이다. 정면을 확신하지 못한 경우는 지금처럼 빠진 정면으로 다시 묻는다
- [x] 후보 제시 지시문이 언제 후보 하나를 내는지 알린다
- [x] `GLOSSARY.md`의 후보 제시, `docs/plan.md`를 고친다

## Comments

### 2026-11-03 구현

- `CANDIDATES_SCHEMA`의 후보 수를 1~4개로 바꿨다. `candidateDiversityChecker`는 후보가 하나인데 두께 선택 노출이 "AI 판단"이면 `(최상위)` 오류로 다시 묻는다. 정면을 확신하지 못했으면 빠진 정면 검사가 그대로 잡는다.
- 메모가 슬라이더를 하나로 정했는지는 자유 문장이라 검사하지 않는다. 지시문이 언제 후보 하나를 내는지 알린다(정면 하나, 두께 선택 노출이 정해짐, 메모가 구성을 하나로 정함). 모델이 그렇지 않은데도 하나만 내면 운영자가 반려한다.
- 문서: `docs/spec-schema.md`의 후보 절, `GLOSSARY.md`의 후보 제시, `docs/plan.md`.
- 시험: `pipeline.test.ts` 2개(정해진 구성이면 후보 하나로 제출까지, 두께 선택 노출이 AI 판단이면 다시 묻기).

### 리뷰 뒤 반영

- 지시문 첫 줄이 "후보 2~4개"로 남아 새 줄과 부딪쳤다. "1~4개, 보통 2~4개"로 고쳤다. `GLOSSARY.md`의 후보 제시 첫 문장도 같다.
- 후보 하나뿐인 회차에서 그 후보가 검증을 통과하지 못하면, 후보 제시로 돌아가도 같은 후보뿐이라 자동으로 고르는 실행 도구(`run-pipeline.ts`)에서 끝없이 돌았다. 그 경우 후보 제시 단계에서 멈추고, 정보 입력의 메모나 두께 선택 노출을 바꾸라고 알린다. 시험 1개를 더했다.
- 반려 이유를 따른 구성이 반려된 후보와 같을 수밖에 없으면 같은 구성을 다시 내고 summary에 반영을 적으라고 지시문에 더했다. 사람이 회차마다 고르므로 끝없이 돌지는 않는다.
- 남긴 것: 후보 하나의 diff를 "다른 구성 없음"으로 쓰라는 지시는 스펙에 없지만, 운영자가 카드에서 다른 구성이 없음을 바로 알 수 있어 그대로 둔다.
