# 13: 두께 고정 실측과 두께 교차 검증

**What to build:** 슬라이더를 움직이는 동안 고른 두께가 변하지 않는지 형상으로 실측하고, 두께 후보와 각 슬라이더를 함께 바꾼 조합도 교차 검증한다. 자식 수식에 두께가 비율로 섞인 경우도 잡는다.

**Blocked by:** 12 (두께 선택)

**Status:** ready-for-agent

- [x] 단독 스윕 전체에서 각 부품의 판재 두께 실측이 변하면 `thickness_change` 피드백이 나온다
- [x] 피드백이 "슬라이더 X가 부품 Y의 두께를 바꿈" 형태로 원인을 가리킨다
- [x] 두께 후보마다 각 슬라이더와의 교차 검증 샘플을 받아 덧셈을 확인하고, 실패하면 격자 보강 규칙을 따른다
- [x] 두께가 수식에 섞인 녹화본으로 경계 1 테스트가 있다

## Comments

### 2026-10-29 구현

- 두께 고정 실측(`pipeline/verify-thickness.ts`의 `verifyThicknessFixed`): 슬라이더마다 단독 스윕 전체의 샘플·검증점(위상 묶음이 닿으면 묶음 안 단독 스윕도)에서 판 두께를 Fusion 형상으로 재고, 위상 묶음 기준 형상의 간격에서 0.2 mm를 넘게 바뀌면 `thickness_change`(`path` `sliders[i]`, 슬라이더·부품마다 가장 크게 바뀐 곳 하나). 힌트는 "슬라이더 body_w가 부품 Carcass의 두께를 바꿉니다: 판 두께(…)가 300에서 18 mm → 9 mm. …". 판은 수치 검증의 판재 두께와 같은 면 쌍이며, `verify-numeric.ts`의 `panelReader`로 나눠 함께 쓴다. 스윕 순회(`sliderSweeps`·`sweepPoint`)도 수치 검증과 같이 쓴다.
- 실행기 순서: 범위 → 두께 고정 실측 → 수치 검증 → 축 반응 → 교차 검증. 비율 수식이면 엔진 보간이 Fusion과 맞아 수치 검증은 통과하고, 비선형 수식이어도 판 두께 치수 오차보다 원인을 가리키는 피드백이 먼저 나온다.
- 두께 교차 검증(`pipeline/verify-cross.ts`): 교차 검증 요청에 슬라이더 쌍 모서리 다음으로 두께 선택마다·기본 두께가 아닌 후보마다·슬라이더마다 범위 끝 2곳을 붙인다. 쌍은 `[두께 선택의 첫 파라미터, 슬라이더]`이고 피드백은 `path` `thickness[i].options`, `slider`는 함께 움직인 슬라이더다. 두께 쌍에서 판 두께가 어긋나면 `thickness_change`("슬라이더 body_w가 두께 t=24에서 부품 Carcass의 두께를 바꿉니다")다. 슬라이더가 하나여도 두께 선택이 있으면 교차 검증을 한다.
- 격자 보강 규칙 그대로: 처음 실패는 피드백, 같은 후보 다음 명세에서도 실패하면 두께 후보(기본 두께 제외) × 슬라이더 min·default·max 격자와 마디 사이 검증점을 `kind` `grid`로 받는다. 2쌍 상한에 함께 센다. `grids`에 `parameters: ["t", "body_w"]`로 담기고, 엔진은 고른 후보의 나머지(격자 샘플 - 슬라이더 이동량 - 두께 후보 이동량)를 슬라이더 값으로 선형 보간해 더한다. 기본 두께에서는 더하지 않는다.
- 합성 녹화본(SolidCraft로 `drawer.sc`를 고쳐 만듦):
  - `solidcraft-test/drawer-ratio-t.sc` → `drawer-ratio-t.json`: 몸통 셸 두께 = `body_w * 0.03`(두께 고정 위반).
  - `solidcraft-test/drawer-mixed-t.sc` → `drawer-mixed-t.json`, `drawer-mixed-t.samples.json`: 사용자 파라미터 `t`(18 mm)가 몸통 셸 두께이고, 서랍 폭 `d5 = body_w - 40 mm + (body_w - 600 mm) * (t - 18 mm) / 60 mm`(자식 수식에 두께가 비율로 섞임). 추가 샘플은 두께 후보 형상·교차 검증·격자·격자 검증점.
  - `shelf.thickness-cross.json`: 칸막이 선반 t=15·24 × 전체 폭 500·1300, 전체 깊이 200·400.
- 시험: 경계 1(비율 두께 → `thickness_change`, 선반 두께 교차 검증 요청과 통과, 섞인 두께 → 첫 피드백 뒤 격자 보강해 제출, 두께 후보에서 판 두께 변화, 두께 격자 샘플 재계산 실패, 두께 격자 검증점 실패). 엔진(두께 격자가 마디 사이 Fusion 형상과 합격선 안, 격자 없이는 넘음, 마디에서 일치, 기본 두께는 그대로).

### 설계 판단

- 두께 격자는 슬라이더 쌍 격자처럼 기본 묶음에서만 쓴다. 슬라이더 범위가 다른 위상 묶음에 닿으면 범위 끝 격자 샘플의 면 구성이 기본 형상과 달라 보강하지 않으므로(`topology_change`), 보강한 슬라이더가 고른 두께에서 묶음을 넘어 보정이 사라지는 일은 없다.
- 두 두께 선택을 함께 바꾼 조합은 이번에도 보지 않는다(`spec-schema.md`에 적었다).

### 리뷰 반영

- 두께 고정 실측을 슬라이더 범위 안이 아니라 단독 스윕 전체로 넓혔다(티켓 문구).
- 두께 고정 실측을 수치 검증 앞으로 옮겼다. 기존 시험 도우미 `pushMaxSide`가 바깥 면만 밀어 판 두께까지 바꾸던 것을, 판을 통째로 미는 것으로 고쳤다(그 시험의 뜻은 W 치수 오차다).
- 두께 쌍에서 판 두께가 어긋나면 `dimension_error` 대신 `thickness_change`로 원인을 가리킨다.
- 엔진에 `findPair`(쌍 판정)·`nonDefaultOptions`·`thicknessValues`를 내보내 교차 검증·수치 검증·조립이 같이 쓴다. 엔진은 두께 격자를 `ids[0]`로 찾는다(교차 검증과 같은 기준).
- 쌍 종류 분기를 `pairWords` 하나로 모았다. 두께 쌍 힌트는 "두께 t와 body_w를 함께 움직이면…"으로 슬라이더 쌍과 같은 문장 틀이다.
- 격자 마디 나머지 계산을 엔진의 `residualOf`로 모았다.
- 용어집에 두께 쌍·두께 고정 실측을 따로 올렸다.
- 시험 추가: 두께 후보에서의 판 두께 변화, 두께 격자 샘플 재계산 실패, 두께 격자 검증점 실패.

### 리뷰에서 반영하지 않은 것

- 두께 쌍이 격자 2쌍 상한에 함께 세어지는 시험: 실행기는 슬라이더 쌍과 두께 쌍을 구분하지 않고 같은 `needed` 목록으로 센다(상한 시험은 티켓 09에 있다). 세 쌍이 실패하는 두께 녹화본을 새로 만드는 비용에 비해 얻는 것이 적다.
- 두께 교차 샘플이 슬라이더 범위 끝 2곳뿐이라 중간에서만 드러나는 수식을 놓칠 수 있다는 지적: 슬라이더 쌍도 모서리만 보는 ADR-0004와 같은 방식이다.
