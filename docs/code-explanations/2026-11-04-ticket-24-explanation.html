티켓 24: SolidCraft 합성 녹화본

Fusion 실물로 녹화본을 만들기 어려운 동안 쓸 시험 데이터를 SolidCraft로 만든다. 스크립트가 SolidCraft 모델의 파라미터를 단독 스윕해, 애드인과 같은 업로드 묶음 형식의 파일을 낸다.

배경

업로드 묶음과 스윕이 낯설다면 펼쳐서 읽는다.

이 프로젝트는 Fusion 모델을 쇼핑몰의 three.js 구성기로 바꾼다. 구성기는 브라우저에서 Fusion을 다시 계산할 수 없으므로, Fusion 애드인이 업로드 때 파라미터를 하나씩 바꿔 가며 형상을 미리 뽑아 둔다. 그 결과 묶음이 업로드 묶음이고, 파라미터 하나만 움직여 뽑은 형상 모음이 단독 스윕이다(티켓 01).

개발자가 Fusion 실물로 이 묶음을 만들어 줘야 뒤 티켓들을 시험할 수 있는데, 실제 상품 녹화본은 공개 저장소에 올릴 수 없고 Fusion을 돌릴 환경도 늘 있는 것은 아니다. 그래서 같은 형식의 시험 데이터를 다른 도구로 만든다.

SolidCraft는 이 프로젝트가 쓰는 독립 파라메트릭 CAD 프로그램이다. 명령행 도구 solidcraft-cli는 호출할 때마다 설계 파일을 새로 열어 명령 스크립트를 실행하고 JSON 결과를 돌려준다. 이 티켓에서 만드는 합성 녹화본(용어집: SolidCraft 등 Fusion이 아닌 도구로 만든 시험용 업로드 묶음)은 실제 상품이 아니므로 저장소에 둘 수 있고, 녹화본 대신 쓴다.

티켓 01에서 애드인 핵심 run_upload가 Fusion을 FusionModel 인터페이스(Protocol) 뒤로 숨겨 두었다. 같은 인터페이스를 SolidCraft로 구현하면 스윕 순서와 묶음 조립은 그대로 재사용할 수 있다. 이 티켓의 설계 전체가 이 한 가지 기회에 기댄다.

핵심 개념 면 이름과 모서리 이름(ADR-0016): SolidCraft는 면에 피처 기준 이름을 붙이고, 모서리는 맞닿는 두 면 이름을 세로선으로 이은 면A|면B로 부른다. 같은 쌍의 모서리가 여럿이면 ~순번이 붙는다. 이 이름은 샘플 사이에서 같은 면을 짝짓는 열쇠가 된다. 이 티켓은 이름과 모서리 끝점을 빠짐없이 담는 일까지 하고, 점 배치를 이름에 맞추는 일은 티켓 25에서 한다.
알려진 한계 이 티켓의 격자는 면의 경계 범위(사각 범위)에 n×n 점을 깐다. 구멍이 있는 면에서는 일부 점이 면 밖의 표면 위에 찍힌다. 코드 주석이 이 점을 티켓 25(경계 맞춤 격자)로 미뤘다고 적어 두었다.

핵심 아이디어

Fusion 어댑터가 하는 일을 SolidCraft로 흉내 낸다. 다만 solidcraft-cli가 호출마다 설계를 새로 열기 때문에, 어댑터는 "지금 바뀌어 있는 파라미터 값"을 자기 기억(_overrides)에 두고, 형상이 필요할 때마다 그 값들을 처음부터 다시 적용하는 스크립트를 한 번에 돌린다. 원본 설계 파일은 저장하지 않으므로 바뀌지 않는다.

예를 들어 body_w를 기본값의 0.75배로 스윕하는 샘플 하나를 뽑을 때, CLI 스크립트는 이런 명령을 순서대로 담는다: 파라미터 변경, 문서 검사(피처 오류 확인), 바디마다 면 목록과 모서리 목록, 바디 측정. 결과 한 덩어리에서 재계산 성공 여부, 면과 모서리, 부피와 바운딩 박스가 모두 나온다. restore_parameter는 기억에서 해당 값을 빼기만 하면 되므로 "되돌리기"가 공짜다.

그 위에 얹은 변화는 세 가지다.

  • 업로드 묶음 스키마에 선택 필드를 더했다: source, 면의 name과 geometry, 샘플의 edges와 bodies. 스키마가 additionalProperties: false라서 필드를 더하지 않으면 새 데이터가 검사에서 거절된다. 모두 선택 필드이므로 기존 묶음은 그대로 유효하다.
  • 애드인 핵심 run_upload가 source와 extra_sweeps를 받는다. 사용자 파라미터가 아닌 스케치 치수(서랍장의 d6 같은 것)도 이름을 넘기면 함께 스윕한다.
  • 평면과 원기둥 면의 격자 점을 직접 계산하는 synthetic/grid.py를 새로 만들었다. SolidCraft에는 (u,v)에서 좌표를 얻는 계산이 없기 때문이다.

합성 녹화본이 만들어지는 흐름(예시 데이터)

drawer.sc + --extra d6
body_w = 0.75배
SolidCraftModel: 명령 스크립트 조립
면·모서리·부피 JSON
solidcraft-cli run
면별 n×n 점
run_upload: 묶음 조립
묶음 JSON
bundle_errors 통과 때만 파일 쓰기
조용한 실패 SolidCraft는 속 비우기가 실패해도 피처 오류를 내지 않는다. 티켓 구현 기록은 body_d=10에서 면만 줄고 오류가 없었다고 적었다. 그래서 recompute_failed는 피처 오류가 있을 때만 붙는다. 이런 조용한 실패는 티켓 10의 위상 비교가 잡을 몫이라고 기록되어 있다.

코드 따라가기

흐름: 명령행 스크립트 → SolidCraft 어댑터(CLI 실행, 상태 캐시) → 격자 계산 → 애드인 핵심의 묶음 조립 → 스키마와 점 수 검사 → 파일 쓰기.

1. 진입점: 묶음을 파일로 쓰는 "서버"

스크립트는 애드인 핵심 run_upload를 그대로 부른다. 서버 자리에는 업로드 대신 묶음을 검사해 파일로 쓰는 BundleFile을 꽂는다. 검사는 서버가 쓰는 bundle_errors 그대로이므로 합성 녹화본은 서버가 받는 녹화본과 같은 기준을 통과한다.

synthetic/make_recording.py:25-47

class BundleFile:
    """업로드 대신 묶음을 검사해 파일로 쓰는 ServerClient."""

    def __init__(self, path: Path) -> None:
        self.path = path

    def ping(self) -> bool:
        return True

    def upload(self, bundle: dict[str, Any]) -> str:
        errors = bundle_errors(bundle)
        if errors:
            raise ValueError("업로드 묶음 검사 실패:\n" + "\n".join(errors))
        self.path.parent.mkdir(parents=True, exist_ok=True)
        self.path.write_text(json.dumps(bundle, ensure_ascii=False), encoding="utf-8")
        return str(self.path)


def make_recording(design: Path, out: Path, extra: list[str], cli: str | None = None) -> Path:
    model = SolidCraftModel(cli_runner(design, cli))
    written = run_upload(model, BundleFile(out), print, source="solidcraft", extra_sweeps=extra)
    assert written is not None
    return Path(written)

검사에 실패하면 예외가 나고 파일은 쓰이지 않는다. 평면과 원기둥이 아닌 면이 있을 때의 오류도 같은 방식으로 파일을 쓰기 전에 끝난다. 이 스크립트가 애드인 핵심을 불러 쓰려고 addin/ConfiguratorUploader를 sys.path 맨 앞에 넣는 것(synthetic/make_recording.py:16-17)이 애드인과 서버, 합성 쪽을 한 저장소에서 이어 붙이는 방법이다.

2. 애드인 핵심의 확장

핵심은 두 곳이 바뀌었다. 먼저 run_upload가 source(기본 "fusion")와 extra_sweeps를 받아, 스윕 대상을 "사용자 파라미터이거나 이름을 넘긴 것"으로 넓힌다.

다음으로 형상 하나를 JSON으로 만드는 _shape_json이 생겼다. 면은 항상 담고, 모델이 TopologyModel(모서리와 바디 측정값을 주는 모델)이면 edges와 bodies도 담는다. TopologyModel은 별도의 runtime_checkable Protocol이다. 새 메서드를 FusionModel에 넣지 않고 따로 둔 덕분에 Fusion 어댑터는 코드를 바꾸지 않았다(티켓 구현 기록도 "Fusion 어댑터는 바뀌지 않았다"고 적었다). 따로 둔 이유는 코드에 적혀 있지 않다. 어댑터가 새 메서드를 구현하지 않아도 되게 하려는 것으로 읽히는데, 이것은 내 추정이다.

def _shape_json(model: FusionModel) -> dict[str, Any]:
    """현재 형상의 면과, 모델이 주면 모서리와 바디 측정값."""
    shape: dict[str, Any] = {"faces": [_face_json(f) for f in model.sample_faces(GRID_N)]}
    if isinstance(model, TopologyModel):
        shape["edges"] = [
            {"body": e.body, "name": e.name, "start": list(e.start), "mid": list(e.mid), "end": list(e.end)}
            for e in model.sample_edges()
        ]
        shape["bodies"] = [
            {"name": b.body, "volume": b.volume, "bbox": {"min": list(b.bbox_min), "max": list(b.bbox_max)}}
            for b in model.measure_bodies()
        ]
    return shape

재계산이 실패한 샘플은 여전히 {"faces": []}만 담는다(addin/ConfiguratorUploader/uploader/core.py:128-129).

3. SolidCraft 어댑터: CLI 실행

실행기는 명령 목록을 임시 폴더의 JSON 스크립트로 쓰고 solidcraft-cli run을 부른다. 설계 파일은 --in으로 읽기만 한다. --allow-errors는 피처가 실패해도 결과를 받아 재계산 실패로 기록하기 위한 옵션이다(코드 주석).

synthetic/solidcraft_model.py:28-48

def cli_runner(design: Path, cli: str | None = None) -> Runner:
    """명령 목록을 `solidcraft-cli run --in design`으로 돌려 명령별 결과를 돌려주는 실행기."""
    exe = cli or os.environ.get("SOLIDCRAFT_CLI", DEFAULT_CLI)

    def run(commands: list[dict[str, Any]]) -> list[Any]:
        with tempfile.TemporaryDirectory() as tmp:
            script, out = Path(tmp) / "script.json", Path(tmp) / "out.json"
            script.write_text(json.dumps({"commands": commands}), encoding="utf-8")
            # --allow-errors: 피처가 실패해도 결과를 받아 재계산 실패로 기록한다
            done = subprocess.run(
                [exe, "run", str(script), "--in", str(design), "--results", "--allow-errors", "--json-out", str(out)],
                capture_output=True,
                text=True,
                encoding="utf-8",
            )
            if done.returncode != 0 or not out.is_file():
                raise RuntimeError(f"solidcraft-cli 실행 실패({done.returncode}): {done.stderr.strip()}")
            result: list[Any] = json.loads(out.read_text(encoding="utf-8"))
            return result

    return run

4. SolidCraft 어댑터: 상태 하나를 한 번에 얻기

_state가 어댑터의 중심이다. 지금의 파라미터 덮어쓰기 목록(key)이 지난번과 같으면 캐시를 돌려주고, 다르면 스크립트를 조립해 CLI를 한 번 돌린다. 스크립트는 파라미터 변경, 문서 검사, 바디마다 면과 모서리, 바디 측정 순이다.

synthetic/solidcraft_model.py:109-139

    def _state(self) -> dict[str, Any]:
        key = tuple(self._overrides.items())
        if self._cache is not None and self._cache[0] == key:
            return self._cache[1]
        commands: list[dict[str, Any]] = [
            {"command": "parameters.change", "params": {"name": n, "expression": e}} for n, e in key
        ]
        commands.append(
            {"command": "document.inspect", "params": {"sketches": False, "measure": False, "joints": False}}
        )
        for body in self._bodies:
            commands.append({"command": "model.faces", "params": {"body": body}})
            commands.append({"command": "model.edges", "params": {"body": body}})
        commands.append({"command": "inspect.measure", "params": {}})
        try:
            results = self._run(commands)
        except RuntimeError:
            # 바디가 사라지는 등 명령 자체가 실패한 경우
            state: dict[str, Any] = {"ok": False}
        else:
            changes, inspected = results[: len(key)], results[len(key)]
            per_body = results[len(key) + 1 : -1]
            ok = not any(c["errors"] for c in changes) and not any(f["error"] for f in inspected["timeline"])
            state = {
                "ok": ok,
                "faces": {per_body[2 * i]["body"]: per_body[2 * i]["faces"] for i in range(len(self._bodies))},
                "edges": {per_body[2 * i + 1]["body"]: per_body[2 * i + 1]["edges"] for i in range(len(self._bodies))},
                "bodies": results[-1]["bodies"],
            }
        self._cache = (key, state)
        return state

재계산이 성공했다는 판정(ok)은 "파라미터 변경 명령이 오류를 내지 않았고, 타임라인에 오류 피처가 없다"이다. 명령 자체가 실패하는 경우(바디가 사라지는 등)는 RuntimeError로 잡아 ok: False로 기록한다. set_parameter는 이 상태의 ok를 돌려주고, restore_parameter는 덮어쓰기에서 이름을 빼기만 한다(synthetic/solidcraft_model.py:98-107). mm가 아닌 단위의 파라미터는 아직 바꿀 수 없어서 ValueError를 낸다.

5. 면 이름과 모서리 이름 풀기

모서리 이름 면A|면B를 두 면으로 나눌 때 단순히 세로선에서 자르면 안 된다. 필렛 면 이름(F3:blend:F1:-x|F1:-y)에도 세로선이 들어 있기 때문이다. edge_faces는 세로선마다 "왼쪽도 오른쪽도 실제 면 이름인 자리"를 찾는다.

synthetic/solidcraft_model.py:55-64

def edge_faces(edge_name: str, face_names: set[str]) -> tuple[str, str]:
    """모서리 이름 "면A|면B" 또는 "면A|면B~순번"을 두 면 이름으로 나눈다.

    필렛 면 이름(F3:blend:F1:-x|F1:-y)에도 세로선이 있으므로, 나눈 두 쪽이 모두 면 이름인 자리를 찾는다.
    """
    base = edge_name.rsplit("~", 1)[0] if "~" in edge_name else edge_name
    for i, ch in enumerate(base):
        if ch == "|" and base[:i] in face_names and base[i + 1 :] in face_names:
            return base[:i], base[i + 1 :]
    raise ValueError(f"모서리 {edge_name}: 두 면 이름으로 나눌 수 없습니다")

6. 면마다 격자 점 찍기

sample_faces는 바디의 모든 면을 돌며, 그 면이 포함된 모서리를 모아 경계로 삼고, 면의 종류에 따라 격자를 부른다. 원기둥은 cylinder 정보가, 평면은 plane_normal이 있다. 둘 다 없으면 면 이름과 함께 오류를 내고, 앞의 BundleFile이 쓰이기 전이므로 파일은 만들어지지 않는다.

synthetic/solidcraft_model.py:141-162

    def sample_faces(self, grid_n: int) -> list[FaceSample]:
        state = self._state()
        samples = []
        for body in self._bodies:
            names = {f["name"] for f in state["faces"][body]}
            edge_pairs = [(edge_faces(e["name"], names), e) for e in state["edges"][body]]
            for face in state["faces"][body]:
                name = face["name"]
                bound = [_edge(e) for pair, e in edge_pairs if name in pair]
                if face.get("cylinder"):
                    c = face["cylinder"]
                    origin, axis, radius = _point(c["origin"]), _point(c["axis"]), float(c["radius"])
                    surface, points = "cylinder", cylinder_grid(origin, axis, radius, bound, grid_n)
                    geometry = {"type": "cylinder", "origin": list(origin), "axis": list(axis), "radius": radius}
                elif face.get("plane_normal"):
                    normal = _point(face["plane_normal"])
                    surface, points = "plane", plane_grid(normal, bound, grid_n)
                    geometry = {"type": "plane", "normal": list(normal)}
                else:
                    raise UnsupportedFaceError(f"{body} 면 {name}: 평면과 원기둥만 다룹니다")
                samples.append(FaceSample(body=body, surface=surface, points=points, name=name, geometry=geometry))
        return samples

평면 격자는 경계 모서리 점(시작, 중간, 끝, 원호의 가장 바깥 점)을 면 안의 두 축 u, v에 투영해 최솟값과 최댓값으로 사각 범위를 정하고 그 범위를 n등분한다. 두 축은 법선과 가장 덜 평행한 월드 축으로 잡아 샘플이 달라도 같은 규칙으로 정해진다.

def plane_grid(normal: Vec, edges: list[Edge], n: int) -> list[Vec]:
    """평면 면의 경계 범위에 n×n 점을 찍는다."""
    u, v = _frame(normal)
    origin = _mul(_unit(normal), _dot(edges[0].start, _unit(normal)))
    points = _edge_points(edges, [u, v])
    us = [_dot(_sub(p, origin), u) for p in points]
    vs = [_dot(_sub(p, origin), v) for p in points]
    return [
        _add(origin, _add(_mul(u, pu), _mul(v, pv)))
        for pu in _steps(min(us), max(us), n)
        for pv in _steps(min(vs), max(vs), n)
    ]

원기둥 격자는 u가 각도, v가 축 방향이다. 경계 점들의 각도를 덮는 가장 짧은 호(가장 큰 빈틈의 반대쪽, synthetic/grid.py:124-130)와 축 방향의 최소~최대를 범위로 삼는다. 반원기둥이나 필렛 사분원기둥에서도 해당 각도 범위에만 점이 찍힌다는 것이 시험의 내용이다(test_필렛_사분원기둥은_90도_범위에만_점을_찍는다).

SolidCraftModel은 바꾼 파라미터 값을 기억해 두고 형상이 필요할 때마다 처음부터 다시 적용한다. 이렇게 한 이유로 가장 알맞은 것은?

CLI는 호출이 끝나면 상태를 버리고 다음 호출에서 설계를 다시 연다. 그래서 파라미터 변경 명령을 매번 같은 스크립트 앞에 붙여야 하고, restore_parameter는 기억에서 빼기만 하면 된다. 원본 파일이 바뀌지 않는 것은 저장하지 않기 때문이다.

모서리 이름 A|B|C이고 이 바디의 면 이름이 A|B와 C뿐이라면 edge_faces는 무엇을 돌려줄까?

첫 세로선(앞이 A)은 A가 면 이름이 아니라 건너뛰고, 둘째 세로선은 앞 A|B와 뒤 C가 모두 면 이름이라 거기서 나눈다. 필렛 면 이름처럼 이름 자체에 세로선이 있어도 풀리는 이유다.

속 비우기가 조용히 실패해 면만 줄어들고 피처 오류는 없다. 이 티켓의 코드는 그 샘플을 어떻게 기록할까?

ok는 변경 명령 오류와 타임라인 오류 피처로만 정한다. 면 수나 부피는 판정에 쓰지 않는다. 이런 조용한 실패는 위상 비교를 하는 티켓 10이 맡는 것으로 기록되어 있다.

_shape_json이 isinstance(model, TopologyModel)로 모서리와 바디 측정값을 담을지 정한다. FusionModel 자체에 메서드를 더하는 대신 이렇게 한 효과는?

FusionModel에 메서드를 더하면 실제 Fusion 어댑터도 구현해야 하고, 이 환경에서는 그것을 시험할 수 없다. 별도 Protocol이면 어댑터는 손대지 않는다. 두 필드가 선택 필드인 것은 스키마가 정하는 일이라 이 구조와 별개이고, 면 짝짓기는 이 티켓 범위가 아니다.
