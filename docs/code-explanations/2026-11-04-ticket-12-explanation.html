티켓 12: 두께 선택

명세에 두께 선택을 쓸 수 있게 하고, 고객이 구성기의 두께 슬롯에서 표준 두께 목록의 앞뒤 한 칸 중 하나를 고르면 형상이 그 두께로 바뀌게 한 변경이다.

jun-1993-p/threejs-configurator-ai 티켓 12 (커밋 6c05d18), 2026-11-04에 설명함. References link to this commit.

배경

이 프로젝트가 처음이라면: 깊은 배경을 펼치세요.

프로젝트는 Fusion CAD 모델을 쇼핑몰 페이지의 div 안에서 도는 three.js 구성기로 바꾼다. CAD 애드인이 업로드 때 파라미터 값을 바꿔 가며 형상을 미리 뽑아 두고(스윕), 구성기의 변형 엔진은 그 샘플들 사이의 꼭짓점 이동량을 슬라이더 값에 맞춰 섞는다. 슬라이더 둘을 함께 움직이면 각 단독 스윕의 이동량을 더한다(ADR-0004).

파이프라인은 업로드 뒤에 명세(어떤 슬라이더를 어떤 범위로 노출할지 적은 JSON)를 AI가 쓰게 하고, 명세 검사와 수치 검증을 거친다. 검증 중에 서버가 연결된 애드인에 형상을 더 요청할 수 있다. 이것이 추가 샘플 요청이다(티켓 08). 요청은 파라미터 이름과 값을 짝지은 값 묶음 여러 개이고, 애드인은 값 묶음마다 형상을 돌려준다.

판재 두께는 처음에 완전히 고정이었다(두께 고정). 그러나 두께를 고르고 싶다는 고객 요구가 있어 ADR-0010이 두께 선택을 더했다. 두께 선택은 슬라이더가 아니다. 고객은 연속 값을 끌지 않고 목록에서 후보 하나를 고른다. 후보는 기본 두께의 ±3 mm가 아니다. ADR이 든 까닭은 이렇다. 18t에서 3 mm를 더하면 21 mm인데 주문할 수 없는 두께다. 그래서 고정 코어에 한국 표준 두께 목록(3·6·9·12·15·18·24·30 mm)을 두고, 기본 두께의 앞뒤 한 칸을 후보로 삼는다. 목록 끝(3t, 30t)은 후보가 2개다.

용어

기본 두께는 업로드한 모델에 들어 있는 판재 두께 파라미터의 값이다. 두께 후보는 표준 두께 목록에서 기본 두께와 그 앞뒤 한 칸이다. 두께 후보 형상은 다른 파라미터는 그대로 두고 두께만 후보로 바꾼 Fusion 형상이다. 몸통 판재 여러 장이 같은 두께를 쓰면 한 두께 선택에 ids로 묶는다.

이 티켓은 티켓 11이 만든 위상 묶음 위에 선다. 폭을 움직이면 칸막이 수가 바뀌는 선반에서는 면 구성이 묶음마다 다르다. 그래서 두께 후보 형상도 묶음마다 필요하다.

핵심 아이디어

두께 후보 하나는 "기준 형상에서 두께만 바꾼 형상"으로 쓰인다. 이 형상과 기준 형상의 꼭짓점 차이가 그 후보의 이동량이다. 고객이 후보를 고르면 엔진은 기준 위치에 슬라이더 이동량을 더하고, 고른 후보의 이동량도 더한다. 후보 사이 값은 없으므로 보간하지 않는다. 기본 두께를 고르면 더할 것이 없다.

고객이 24t를 고른 채 폭을 위상 경계 너머로 옮겨도 두께가 유지되어야 한다. 티켓 기록은 기본 묶음에서만 후보 형상을 받으면 이 순간 두께가 기본으로 돌아간다고 적었다. 격자 보강(덧셈이 틀리는 슬라이더 쌍을 3×3 격자 샘플로 보강하는 일)은 기본 묶음에서만 쓰는데, 두께 후보 형상은 위상 묶음마다 받는다는 점이 다르다. 이 티켓은 후보 형상을 위상 묶음마다 받는 쪽을 택했다.

코드 따라가기

흐름: 표준 두께 목록 → 명세 검사 → 받을 형상의 계획 → 실행기가 요청해 조립 → 받은 형상 검사 → 엔진이 후보 이동량을 더함 → 구성기의 두께 슬롯.

1. 고정 코어: 표준 두께 목록과 후보 계산

고정 코어(AI가 바꾸지 않는 구성기·엔진·검증기 코드) 중 구성기와 검증기가 같이 쓰는 파일에 목록과 후보 계산이 들어가므로, 명세 검사도 같은 목록을 쓴다.

configurator/src/engine.ts:26

export const STANDARD_THICKNESSES = [3, 6, 9, 12, 15, 18, 24, 30] as const;

configurator/src/engine.ts:29-32

export function thicknessOptions(base: number): number[] {
  const i = STANDARD_THICKNESSES.findIndex((t) => t === base);
  return i === -1 ? [] : STANDARD_THICKNESSES.slice(Math.max(0, i - 1), i + 2);
}

끝에 있으면 Math.max(0, i - 1)이 앞쪽을 0에서 막고, slice가 뒤쪽을 목록 길이에서 막으므로 후보가 2개가 된다. 목록에 없는 값은 빈 목록이다.

2. 명세 검사: 두께 선택이 규칙에 맞는지

형식 검사를 통과한 명세에 configurator/pipeline/schemas.ts:90를 돌린다. 틀린 곳마다 JSON 경로를 붙인 문장이 나오고, 파이프라인은 이를 AI에게 돌려 명세를 다시 쓰게 한다. ids가 업로드 묶음의 파라미터인지, 묶인 파라미터의 기본 두께가 서로 같고 default와 같은지, default가 표준 두께 목록 안인지, options가 thicknessOptions(default)와 같은지 본다.

Fusion 값은 cm에서 바꾼 부동소수라서, 업로드한 모델의 두께와 명세의 두께는 1e-6 mm 안이면 같다고 본다(SAME_THICKNESS_MM). 두께를 슬라이더 이동 중에 움직이지 않게 하는 configurator/pipeline/schemas.ts:117도 함께 돈다. 고정 두께나 두께 선택에 든 파라미터가 어떤 슬라이더의 children에 있으면 거절한다. 코드 주석이 밝힌 까닭은 슬라이더를 움직이는 동안 두께가 변하지 않게 하려는 것이다.

3. 받을 형상의 계획

받을 형상은 configurator/src/engine.ts:218 하나가 정한다. 기본 묶음과, 슬라이더 범위가 닿는 위상 묶음마다 기준 값(anchor)을 붙여 목록을 만들고, 거기에 두께 선택과 기본 두께가 아닌 후보를 곱한다.

configurator/src/engine.ts:218-234

export function thicknessSamplePlan(spec: Spec, data: SweepData): ThicknessSample[] {
  const groups = [
    { baseline: data.baseline, anchor: undefined as GroupAnchor | undefined },
    ...spec.sliders.flatMap((slider) =>
      (data.sweeps.find((s) => s.parameter === slider.id)?.groups ?? [])
        .filter((g) => reaches(slider, g))
        .map((g) => ({ baseline: g.baseline, anchor: { slider: slider.id, value: g.anchor } })),
    ),
  ];
  return groups.flatMap(({ baseline, anchor }) =>
    spec.thickness.flatMap((choice, i) =>
      choice.options
        .filter((o) => o !== choice.default)
        .map((option) => ({ choice: i, option, ...(anchor ? { anchor } : {}), baseline, values: thicknessValues(choice, option, anchor) })),
    ),
  );
}

요청 값 묶음(이 함수가 만들어 서버가 애드인에 보내는 것)과 엔진이 찾는 값 묶음(createGroupMorph가 만드는 것)이 어긋나지 않도록 둘 다 thicknessValues로 값 묶음을 만든다. 티켓 기록은 값 묶음을 이 계획 하나로 정해 어긋나지 않게 했다고 적었고, 파이프라인이 쓰는 이 함수가 엔진 파일에 있는 것도 그 때문이다.

5. 변형 엔진: 후보 이동량을 위상 묶음마다 만들어 더한다

configurator/src/engine.ts:240가 묶음 하나를 만들 때 두께 선택마다 ThicknessTrack을 만든다. 기본 두께가 아닌 후보마다 같은 값 묶음의 샘플을 찾아 그 묶음 기준 형상에서의 이동량으로 저장한다.

configurator/src/engine.ts:329-342

      const delta = deltaOf(sample.faces);

고를 때는 configurator/src/engine.ts:443가 이동량을 더한다. 후보가 아닌 값은 보간하지 않고 오류다.

configurator/src/engine.ts:443-448

function addThickness(out: Float64Array, { choice, deltas }: ThicknessTrack, value: number) {
  if (value === choice.default) return;
  const delta = deltas.get(value);
  if (!delta) throw new Error(`두께 선택 ${choice.ids[0]}: ${value} mm는 후보(${choice.options.join("·")})가 아닙니다`);
  for (let i = 0; i < out.length; i++) out[i] += delta[i];
}

shape는 configurator/src/engine.ts:418에서 이 함수를 부른다. 두께 선택 값은 configurator/src/engine.ts:200가 묶인 파라미터 중 values에 있는 첫 이름에서 읽는다. 처음 구현은 ids[0]만 읽었다가 리뷰에서 고쳤다고 티켓 기록에 적혀 있다.

두께 선택마다 <select> 하나가 생긴다. 고르면 configurator.set이 불리고, 묶인 파라미터 중 아무 이름이든 두께 선택으로 처리해 묶인 파라미터를 모두 같은 값으로 바꾼다. 후보가 아닌 값은 예외를 던진다.

티켓 기록은 Chrome에서 슬롯에 15·18·24 mm가 뜨고, 24t와 15t에서 판이 두꺼워지고 얇아지며, 24t를 고른 채 폭을 600(2칸 묶음)으로 옮겨도 두께가 유지됨을 확인했다고 적었다.

퀴즈

ADR-0010은 두께 후보를 기본 두께 ±3 mm가 아니라 표준 두께 목록의 앞뒤 한 칸으로 정했다. 반대로 ±3 mm 계산이 더 맞았을 상황은?

ADR의 근거는 주문할 수 없는 두께(18t에서 21 mm)가 나온다는 점이다. 임의의 두께를 3 mm 단위로 맞출 수 있다면 그 근거가 사라진다. 연속 값은 후보 사이를 보간하지 않는 이 설계와 맞지 않고, 두께를 바꿔 면 구성이 달라지는 경우는 파이프라인이 topology_change로 거르는 별개의 문제다.

선반 명세에 두께 선택이 하나 있고 후보가 15·18·24, 기본 두께가 18이다. 슬라이더 범위가 닿는 위상 묶음이 기본 묶음을 포함해 2개다. 서버가 애드인에 요청하는 값 묶음은 모두 몇 개인가?

계획은 위상 묶음마다 두께 선택마다 기본 두께가 아닌 후보마다 하나다. 기본 두께 18은 요청하지 않고 15와 24만 남으므로 2 × 1 × 2 = 4개다. 묶음이 3개였다면 6개가 된다.

고객이 두께를 24로 고르고 폭을 1250(4칸 묶음)으로 두었다. 엔진은 어떤 이동량들을 기준 위치에 더하는가?

묶음은 면 구성이 다르므로 이동량은 같은 묶음의 기준 형상에서 잰 것끼리만 더할 수 있다. 폭 1250은 4칸 묶음 안이라 폭 이동량도 24t 이동량도 4칸 묶음의 기준 형상에서 뽑은 것이어야 한다. 그래서 후보 형상을 묶음마다 받는다.

엔진이 두께 선택 값을 ids[0] 이름으로만 읽는다고 하자. 호출하는 쪽이 판재가 둘 묶인 선택에서 둘째 판재 이름으로 24를 주면 결과는?

엔진은 첫째 이름의 값이 없으면 기본 두께로 보고, 둘째 이름의 값은 읽지 않는다. 그래서 두께가 바뀌지 않는다. 지금의 thicknessValueOf는 묶인 이름 중 값이 있는 첫 이름을 읽어 이 문제를 없앴다. 오류는 값이 읽혔는데 후보가 아닐 때만 난다.

명세 검사는 한 두께 선택에 묶인 파라미터의 기본 두께가 서로 다르면 명세를 거절한다. 이 규칙이 필요한 가장 직접적인 이유는?

thicknessValues는 ids의 모든 파라미터를 같은 후보 값으로 채워 요청한다. 기본 두께가 12와 18로 묶여 있으면 둘을 15로 바꾸는 요청이 12에게는 한 칸 위, 18에게는 한 칸 아래라서 후보를 하나의 default로 정할 수 없다. Fusion 제약이나 슬롯 표시는 이유가 아니다.
