# AI 모델은 외부 API를 쓰고 로컬 모델을 예비로 둔다

운영 원칙은 로컬 서버(Docker, LAN)와 무료·오픈소스 구성이지만, LLM과 VLM은 외부 API(Groq)의 무료 등급으로 호출한다. 따라서 상품의 파라미터·명세·렌더링 이미지가 LAN 밖으로 나간다. 이 외부 전송은 받아들인다. 대신 오픈 웨이트 모델만 쓰고 LiteLLM으로 호출을 중계해, 외부 API를 쓸 수 없게 되면 로컬 머신(운영체제나 기종을 한정하지 않음)에서 같은 계열 모델로 바꿀 수 있게 한다. 처음부터 전부 로컬로 돌리면 120b급 모델과 VLM을 감당할 하드웨어가 필요하고 응답이 느리다.

## Consequences

- 원칙 위반처럼 보이는 외부 전송은 의도된 것이다.
- 특정 외부 API나 로컬 환경에만 있는 기능에 기대지 않는다. LiteLLM 뒤에서 모델을 바꿔도 단계별 입출력 형식이 유지되어야 한다.

## 바뀐 것

- 2026-11-03: 처음에는 Cerebras를 먼저 부르고 Groq를 예비로 두었다. Cerebras 가입에 카드 등록이 필요해 빼고, Groq를 첫 모델로 둔다. 예비는 로컬 모델 하나다.
- 2026-11-03: 로컬 예비 LLM·VLM을 뺐다. 당분간 운영·시험 기계인 개발 PC(메모리 16GB 중 Docker 7.7GB, CPU만)에서 `gpt-oss:20b`는 메모리에 들지 않고, `qwen3-vl` 8b·4b·4b-instruct는 부품 탐색 하나에 15분 안에 답하지 못했다(티켓 26 6절). Groq가 실패하면 그 실행은 실패하고, 최종 확인 도구가 끊긴 실행으로 남겨 다시 돌린다. LiteLLM으로 중계하는 구조는 그대로라, 사양이 되는 기계에서는 `docker/litellm/config.yaml`에 로컬 모델과 `fallbacks`를 되살리면 된다. 임베딩은 작아 계속 로컬에서 돈다.
