# 녹화본 만들기

실제 상품의 Fusion 모델로 녹화본을 만드는 절차와 준비 조건. 녹화본은 티켓 02부터 변형 엔진과 파이프라인 실행기를 시험하는 입력이 된다. 용어는 `GLOSSARY.md`를 따른다.

## 1. 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 할 일 | Fusion에서 모델을 업로드한 뒤, 서버에 녹화를 요청한다 |
| 첫 녹화본 | stool1, 또는 슬라이더 1~2개짜리 가장 단순한 실제 상품 하나 |
| 걸리는 시간 | 준비 30분 안팎 + 업로드(사용자 파라미터 수 × 9회 재계산, 위상 묶음이 있으면 더) |
| 결과 | `fixtures/private/recordings/<이름>.json` (공개 저장소에 올라가지 않음) |
| 끝나면 알려줄 것 | 6장의 "전달 항목" |

## 2. 준비물

- Fusion이 설치된 PC. 서버도 같은 PC에서 돌려도 된다.
- Python 3.12 이상(`python --version`으로 확인).
- 이 저장소를 받은 폴더. 아래 명령은 모두 저장소 최상위 폴더에서 실행한다.

## 3. 모델 준비 조건

업로드 전에 Fusion에서 아래를 확인한다. **필수**를 어기면 녹화본을 쓸 수 없고, **권장**을 어기면 쓸 수는 있지만 뒤 티켓에서 다시 만들어야 할 수 있다.

### 필수

1. **파라메트릭 디자인**: 타임라인(화면 아래 작업 기록)이 있어야 한다. 직접 모델링 디자인은 재계산 실패를 판정할 수 없다.
2. **슬라이더로 쓸 치수는 사용자 파라미터**: 수정 → 매개변수 변경에서 "사용자 매개변수"로 만든다. 애드인은 **사용자 파라미터 전부**를 스윕하고, 모델 파라미터(`d12` 같은 스케치 치수)는 스윕하지 않는다.
3. **자식 치수는 수식으로 부모를 참조**: 예를 들어 `서랍폭 = W / 2 - t`처럼 쓴다. 수식은 업로드 뒤에 원래대로 되돌아간다.
4. **업로드 전 타임라인에 오류(빨간 표시)가 없을 것**: 경고(노란 표시)는 괜찮다. 이미 있던 오류는 실패로 치지 않지만, 녹화본의 품질을 보장할 수 없다.
5. **보이는 바디만 상품일 것**: 보이는 바디만 업로드된다. 보조 바디, 참고용 바디, 치수 확인용 바디는 숨긴다(눈 아이콘).
6. **기본값이 0이 아닐 것**: 스윕 범위가 기본값 ±50%라서, 기본값이 0인 파라미터는 범위가 생기지 않는다.

### 권장

1. **부품은 컴포넌트로 나누고 이름을 붙인다**: 예: "상판", "다리", "서랍_1". 부품 이름이 검증 피드백에 그대로 나온다. 같은 컴포넌트를 여러 번 넣으면(좌·우 측판) 서로 다른 부품이 된다.
2. **사용자 파라미터는 실제로 슬라이더 후보인 것만 2~6개**: 하나당 재계산이 9번(샘플 5, 검증점 4)이고, 비선형으로 변하는 파라미터는 적응형 스윕으로 33번(샘플 17, 검증점 16)까지 는다. 그동안 Fusion 화면이 멈춘다.
3. **개수형(정수) 값은 단위 없이 둔다**: 선반 수나 패턴 개수 같은 값이다. 애드인은 단위가 없고 값이 정수인 파라미터를 개수형으로 보고 스윕하지 않으며, 슬라이더 후보에도 올리지 않는다. 단위(mm 등)를 붙이면 연속 치수로 스윕된다.
   - 칸막이 수처럼 치수에 따라 바뀌는 개수는 수식으로 둔다(예: `bays = floor(W / 400 mm) + 1`). 그러면 애드인이 폭 스윕을 칸 수마다 위상 묶음으로 나누고, 구성기에서는 경계에서 칸막이가 바로 나타난다(ADR-0005). 파라미터 하나가 기본값 ±50% 안에서 위상 묶음 4개(개수 값 4가지)를 넘지 않게 한다. 넘으면 범위가 줄어든다.
4. **문서 단위는 mm**: 다른 단위여도 변환되지만 확인이 쉽다.
5. **기본값 ±50%에서도 형상이 깨지지 않게**: 재계산이 깨지는 값이 있으면 애드인이 그 안쪽으로 스윕 범위를 줄이고 `recompute_failed`로 기록한다. 그래도 녹화본은 쓸 수 있지만, 첫 녹화본은 모든 점이 성공하는 편이 좋다.
6. **면은 평면과 원기둥만**: 원뿔(모따기한 구멍), 구, 자유곡면, 원 두 개로 둘러싸이지 않은 원기둥(필렛이 닿은 둥근 다리 등)은 아직 다루지 않아 업로드가 오류로 멈춘다(티켓 26). 원형 구멍, 둥근 다리, 원형 상판처럼 원으로 돌출한 형상은 괜찮다.
7. **판재 두께는 이름으로 구분되게**: 예: `t_body`, `t_back`. 두께 선택(티켓 12)을 준비하는 데 쓴다.

## 4. 절차

4-1부터 4-5까지와 6장의 전달 항목은 위저드가 차례로 안내한다. Git Bash 창에서 저장소 최상위 폴더로 가서 `bash scripts/fusion-recording-wizard.sh`로 실행한다. 4-1의 설치(`.venv`)가 안 돼 있으면 위저드가 먼저 설치를 묻는다. 서버가 떠 있지 않으면 위저드가 띄웠다가 끝날 때 끄고, 녹화본 요점(`.venv/Scripts/python -m scripts.recording_summary <녹화본>`)과 메모를 `fixtures/private/recordings/`에 남긴다.

### 4-1. 서버 띄우기 (처음 한 번 설치)

PowerShell에서 저장소 최상위 폴더로 이동한 뒤 실행한다.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
```

서버를 띄운다. 이 창은 녹화가 끝날 때까지 닫지 않는다.

```powershell
.venv\Scripts\uvicorn server.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 http://localhost:8000/health 를 열어 `{"status":"ok"}`가 보이면 된다.

- 서버를 다른 PC에서 띄운다면 `--host 0.0.0.0`을 쓰고, 4-2의 `SERVER_URL`을 그 PC 주소로 바꾼다.

### 4-2. 애드인 설치 (처음 한 번)

1. Fusion에서 `Shift+S`를 눌러 "스크립트 및 추가 기능" 창을 연다.
2. "추가 기능" 탭에서 `+`를 누르고, 저장소의 `addin/ConfiguratorUploader` 폴더를 고른다.
3. 목록에서 `ConfiguratorUploader`를 골라 "실행"을 누른다.
4. 디자인 작업공간 → 유틸리티 탭 → 추가 기능 패널에 **"구성기 업로드"** 버튼이 생긴다.
5. 서버가 이 PC가 아니면 `addin/ConfiguratorUploader/config.py`의 `SERVER_URL`을 고치고 애드인을 다시 실행한다.

### 4-3. 업로드

1. 3장 조건을 확인한 모델을 연다.
2. **모델을 먼저 저장한다**: 업로드 중에 파라미터를 바꿨다가 되돌리지만, 혹시 모를 문제에 대비한다.
3. "구성기 업로드"를 누른다.
4. Fusion 화면이 멈춘 것처럼 보여도 기다린다. 사용자 파라미터 4개면 재계산이 20번 일어난다.
5. "업로드했습니다: <업로드 ID>" 메시지가 나오면 ID(32자리 영문·숫자)를 복사해 둔다.
6. 완료 창의 "점검" 줄을 본다. 애드인이 업로드 뒤 스스로 잰 결과로, 같은 내용이 `data/addin-checks/<업로드 ID>.json`에도 남는다.
   - `restored`: 업로드 전과 값이나 수식이 달라진 파라미터. 애드인이 다시 되돌리고 이름을 적는다.
   - `proxy_edges`·`moved_occurrences`·`proxy_mismatches`: 컴포넌트 안 바디의 모서리 점과 평면 법선이, 본래 컴포넌트의 것을 오커런스 변환으로 옮긴 것과 0.001 mm·0.001 rad 안에서 같은지. 옮기지 않은 컴포넌트만 있으면 늘 맞으므로 옮긴 오커런스 수도 적는다.
   - `recompute_failures`: 재계산 실패로 판정한 샘플마다 오류 상태인 타임라인 피처.
   - 업로드가 도중에 실패해도 애드인이 바꾼 파라미터를 되돌린다. 그래도 실패한 뒤의 모델은 저장하지 말고 저장해 둔 판으로 다시 연다.

### 4-4. 녹화

서버 창과 다른 PowerShell 창에서 실행한다. 이름에는 영문·숫자·`_`·`-`만 쓰는 것을 권장한다. 한글도 허용되지만, PowerShell 5에서는 인코딩 문제가 날 수 있다.

```powershell
Invoke-RestMethod -Method Post -Uri "http://localhost:8000/uploads/<업로드 ID>/recording" -ContentType "application/json" -Body '{"name": "stool1"}'
```

`name : stool1`이 출력되면 `fixtures/private/recordings/stool1.json`이 만들어진 것이다.

### 4-5. 녹화본 확인

```powershell
.venv\Scripts\python -c "import json,sys; b=json.load(open(sys.argv[1],encoding='utf-8')); print('파라미터', [(p['name'], p['value'], p['unit'], p['is_user']) for p in b['parameters']]); print('부품', [(p['name'], p['kind'], len(p['faces'])) for p in b['parts']]); [print('스윕', s['parameter'], s['range'], [x['status'] for x in s['samples']]) for s in b['sweeps']]" fixtures/private/recordings/stool1.json
```

다음을 확인한다.

- 사용자 파라미터가 빠짐없이 `is_user True`로 나오고, 값이 mm 기준으로 맞다(예: 800 mm 폭이면 800).
- 부품 이름이 Fusion 브라우저의 컴포넌트와 맞고, 부품마다 면 수가 0보다 크다.
- 스윕마다 5개 상태가 나오고, 가능하면 모두 `ok`다.

## 5. 보안

- 저장소는 Public이다. `fixtures/private/`와 `data/`는 `.gitignore` 대상이므로 커밋되지 않는다. 다른 곳으로 옮기거나 이름을 바꾸지 않는다.
- `.f3d`·`.step`·`.stl`·`.obj` 파일도 커밋되지 않는다. 그래도 저장소 폴더 안에는 두지 않는 것이 안전하다.
- 녹화본 백업은 저장소 밖(개인 드라이브 등)에 둔다.

## 6. 끝나면 전달할 것

티켓 02에서는 손으로 명세를 써야 하므로, 아래 내용이 필요하다.

1. **녹화본 이름**(예: `stool1`)과 4-5 확인 명령의 출력 전체
2. **파라미터의 뜻**: 사용자 파라미터마다 "어느 치수인지, 어느 축(W 폭·D 깊이·H 높이)인지, 판매할 때의 대략적인 범위". 예: `W` = 좌판 폭, W, 300~500 mm
3. **부품 설명**: 컴포넌트마다 무엇인지(상판, 다리 등)
4. **정면 방향**: 고객이 마주하는 쪽이 Fusion의 어느 방향인지(예: -Y 쪽이 정면)
5. **Fusion 버전**: 도움말 → Fusion 정보
6. **이상했던 점**: 아래는 Fusion에서 처음 돌리는 부분이라 특히 알려 주면 좋다.
   - 완료 창의 점검 줄에 어긋난 어셈블리 좌표가 있었는지
   - 점검 줄의 재계산 실패 샘플에 적힌 오류 피처가 그 값에서 실제로 깨질 만한 피처인지(모르면 비워 둔다)
   - 점검 줄에 다시 되돌린 파라미터가 있었는지, 녹화본 요점에 "애드인이 쓴 꼴의 수식"이 있었는지
   - 화면 캡처(정면, 측면) 한두 장(선택)

## 7. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| "서버에 연결할 수 없습니다" | 서버 창이 떠 있는지, http://localhost:8000/health 가 열리는지, `SERVER_URL`이 맞는지 |
| "디자인 문서를 연 뒤 실행하세요" | 도면이나 CAM이 아니라 디자인 작업공간에서 실행 |
| "업로드 실패" 창에 긴 오류 문장 | 창의 문장을 전부 복사해서 전달 |
| 모든 샘플이 `recompute_failed` | 업로드 전 타임라인 오류, 수식이 기본값 ±50%를 못 버티는지 확인 |
| 녹화 요청이 422 | 이름에 공백이나 경로 문자(`/`, `.`)가 들어갔는지 확인 |
| 녹화 요청이 404 | 업로드 ID 오타, 또는 서버를 다른 폴더에서 다시 띄웠는지 확인 |
| 버튼이 안 보임 | 스크립트 및 추가 기능 창에서 애드인이 "실행 중"인지 확인 |

## 8. 이후에 필요한 녹화본 (미리 준비하면 좋은 것)

첫 녹화본 다음 티켓들은 아래 성격의 모델을 필요로 한다. 하나의 상품이 여러 항목을 채워도 된다.

| 티켓 | 필요한 모델 |
| --- | --- |
| 05 적응형 스윕 | 슬라이더에 따라 비선형으로 변하는 부분(경사, 원형 패턴)이 있는 모델(합성 녹화본 `fixtures/synthetic/bench-tilt.json`이 있다. Fusion 실물은 아직) |
| 06 축 반응 검증 | 한 축에 슬라이더가 둘인 모델(예: 전체 폭과 서랍 폭) |
| 09 격자 보강 | 두 슬라이더가 서로 영향을 주는 모델(서랍 폭이 전체 폭의 비율을 따라감) |
| 11 위상 묶음 | 폭에 따라 칸막이 수가 바뀌는 모델(합성 녹화본 `fixtures/synthetic/shelf.json`이 있다. Fusion 실물은 아직) |
| 13 두께 고정 실측 | 판재 두께가 수식에 섞인 모델(예: `t = W / 50`) |

교차 검증(티켓 08)부터는 업로드 뒤에도 애드인이 서버에 연결된 채로 추가 샘플에 답한다(ADR-0013). 업로드를 마친 뒤 최종 승인까지 Fusion과 그 디자인 문서를 열어 두어야 한다. 애드인은 3초마다 서버에서 요청을 찾고, 서버는 15초 넘게 소식이 없으면 "Fusion 연결 필요"로 본다.

추가 샘플 응답의 녹화는 아직 서버에 저장하지 않는다. 지금 시험용 교차 검증 샘플은 SolidCraft 합성 녹화본(`python -m synthetic.make_cross_checks`)으로 만든다(`fixtures/synthetic/drawer.cross-corners.json`, `drawer.cross-depth.json`).

## 9. 합성 녹화본 만들기 (SolidCraft, 에이전트용)

Fusion 없이 시험할 모델은 SolidCraft로 만든다(용어집의 합성 녹화본). 평면·원기둥 면만 다룬다.

1. **모델**: SolidCraft MCP로 만든다. 슬라이더가 될 치수는 사용자 파라미터(mm 또는 deg)로 두고 피처 식에서 그 이름을 쓴다. 예: `solidcraft-test/bench-tilt.sc`는 `solid.box` 두 개와 `solid.move {axis, angle: "back_angle"}`.
2. **저장**: MCP는 허용 폴더 밖에 저장하지 못한다. 거부 메시지에 나온 Temp 폴더(`...\Temp\solidcraft-mcp-<번호>-<해시>\`)에 저장한 뒤 `solidcraft-test/`로 복사한다.
3. **녹화**: 저장소 루트에서 `python -m synthetic.make_recording solidcraft-test/<모델>.sc --out fixtures/synthetic/<모델>.json`(사용자 파라미터가 아닌 치수는 `--extra 이름`). 업로드 묶음 검사를 통과해야 파일이 써진다.
4. **시험**: 실제 solidcraft-cli로 다시 녹화하는 시험은 `synthetic/tests/test_make_recording.py`에 두고 `solidcraft` 표시를 붙인다.

SolidCraft의 알려진 동작(면 이름 규칙, 속 비우기 면 지정점, `inspect.parameter_sweep`가 형상 오류를 ok로 보고하는 것 등)은 `solidcraft-test/handoff.md`에 있다.
