# 이슈 트래커: 로컬 마크다운

이 저장소의 이슈와 명세는 `.scratch/` 아래 마크다운 파일로 둔다.

## 규칙

- 기능 하나당 디렉터리 하나: `.scratch/<기능-슬러그>/`
- 명세는 `.scratch/<기능-슬러그>/spec.md`
- 구현 이슈는 티켓 하나당 파일 하나: `.scratch/<기능-슬러그>/issues/<NN>-<슬러그>.md` (`01`부터 번호, 티켓을 한 파일에 합치지 않는다)
- 분류 상태는 각 이슈 파일 상단의 `Status:` 줄에 기록한다 (라벨 문자열은 `triage-labels.md` 참고)
- 댓글과 대화 기록은 파일 맨 아래 `## Comments` 제목 밑에 이어 붙인다

## 일을 다른 티켓으로 미룰 때

미루는 문장에 `미룸(티켓 NN)`을 붙이고, 같은 커밋에서 받는 티켓 본문에 `(티켓 SS에서 옮김)`을 붙인 항목으로 옮긴다(티켓 26이 예). `scripts/tickets.py`가 옮김 표시 없는 미룸을 "미룬 일 빠짐"으로 찍는다.

## 스킬이 "이슈 트래커에 게시"라고 할 때

`.scratch/<기능-슬러그>/` 아래에 새 파일을 만든다 (디렉터리가 없으면 먼저 만든다).

## 다음 티켓 찾기

`python scripts/tickets.py`가 티켓마다 체크 수·"티켓 NN" 커밋·막힘을 찍고 다음 티켓을 고른다. `Status:`는 끝나도 바뀌지 않으므로, 체크가 모두 `[x]`이고 "티켓 NN:" 커밋이 있으면 끝난 티켓이다. 번호가 앞선 열린 티켓이 남아 있으면 그것이 먼저다.

## 스킬이 "해당 티켓을 가져오라"고 할 때

참조된 경로의 파일을 읽는다. 보통 경로나 이슈 번호를 직접 넘겨준다.

## 길찾기(wayfinder) 작업

`/wayfinder`가 사용한다. **지도**는 파일 하나이고 티켓마다 **자식** 파일이 하나씩 있다.

- **지도**: `.scratch/<작업명>/map.md` (메모 / 지금까지의 결정 / 안개 본문)
- **자식 티켓**: `.scratch/<작업명>/issues/NN-<슬러그>.md`, `01`부터 번호, 본문에 질문을 쓴다. `Type:` 줄에 유형(`research`/`prototype`/`grilling`/`task`), `Status:` 줄에 `claimed`/`resolved`를 기록한다.
- **차단**: 상단의 `Blocked by: NN, NN` 줄. 나열된 파일이 모두 `resolved`이면 차단이 풀린다.
- **최전선**: `.scratch/<작업명>/issues/`에서 열려 있고, 차단되지 않았고, 아무도 맡지 않은 파일을 찾는다. 번호가 앞선 것이 먼저다.
- **맡기**: 작업 전에 `Status: claimed`로 바꿔 저장한다.
- **해결**: `## Answer` 제목 밑에 답을 붙이고 `Status: resolved`로 바꾼 뒤, `map.md`의 "지금까지의 결정"에 요지와 링크를 덧붙인다.
