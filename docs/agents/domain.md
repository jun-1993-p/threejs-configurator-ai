# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 읽을지 정한다.

## 탐색 전에 읽을 것

- 루트의 **`GLOSSARY.md`**
- **`docs/adr/`**: 작업할 영역과 관련된 ADR

파일이 없으면 **조용히 넘어간다**. 없다고 알리거나 미리 만들자고 제안하지 않는다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`를 통해 도달)이 용어와 결정이 실제로 정해질 때 필요한 파일을 만든다.

## 구조

단일 컨텍스트:

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── src/
```

## 용어집의 어휘를 쓴다

이슈 제목, 리팩터링 제안, 가설, 테스트 이름 등에서 도메인 개념을 말할 때 `GLOSSARY.md`에 정의된 용어를 쓴다. 용어집이 피하라고 한 동의어로 흐르지 않는다.

필요한 개념이 용어집에 없으면 신호다. 프로젝트가 쓰지 않는 말을 만들어내는 중이거나(다시 생각), 실제 빈틈이다(`/domain-modeling`에 알린다).
